# PF-SCOPE-030 — End listing on web
Status: CLOSED — VERIFIED 2026-11-21 (built + merged as PR #45, main 9621cc38; live acceptance passed same day — see Verification)
Owner approval: APPROVED 2026-11-21 ("Approve PF-SCOPE-030 — build it")
Objective: An item with a live eBay listing can be ended (withdrawn) from the web app's Marketplace panel, and archiving an item with a live listing warns that the listing stays live unless ended first.
Current evidence: PF-SCOPE-004 runbook gap 22 — observed live 2026-11-21 during the PF-SCOPE-029 acceptance: the test item was archived from web while its sandbox listing 110591620696 remained live on eBay, because the web UI offers no way to end it. Code read confirmed the gap is web-UI-only: the backend already exposes `POST /ebay/listings/end` (`endListing()` in `server/ebay-server.mjs`, withdrawing the offer via eBay's Sell Inventory API), and the mobile app already calls it (`endEbayListing` in `apps/mobile/lib/ebay-integration.ts`, persisting the ended state via `markInventoryItemEbayEnded`).
Included:
- `apps/web/src/web-services.js`: new `endEbayListing(offerId)` — `POST /ebay/listings/end` with `{ offerId }` through the same `backendRequest` plumbing as the publish call (the PF-SCOPE-025 timed fetch lives only in the Settings card's own request helper, not in `backendRequest`, so parity means `backendRequest` unchanged). Same contract as mobile's `ebayApi.endListing`.
- `apps/web/src/ebay-publish-state.js`: `hasLiveEbayListing(item)` (keys off `ebayOfferId`, the same guard mobile uses) and `ebayListingEndedUpdate(item)` mirroring mobile's `markInventoryItemEbayEnded` — `ebayStatus: "idle"`, listing id/url/offer id/progress/last-error cleared, `"ebay"` removed from `listedPlatforms`, `ebayUpdatedAt` bumped; `ebaySku` and category stay, as on mobile. Persistence rides the existing item-save path both ways: the local repository serializes whole items, and the Supabase repository's listing-row upsert writes the cleared fields as nulls — no schema or repository changes needed.
- `ListingReview` in `apps/web/src/App.jsx`: an "End listing" button beside "View eBay listing" whenever the item has a live listing, confirmed through the in-app `confirmDialog` (PF-SCOPE-028; no native dialogs), disabled while any platform action is in flight. On success the ended transition is saved via `onSave`; on failure the backend/eBay message shows on the panel's existing error line in the moment (the listing is still live, so the panel keeps showing it) and nothing is persisted.
- Rider: the archive confirmation in the item detail (`remove`) adds "Its eBay listing stays live unless you end it first — archiving will not end it." when the item has a live listing. Warning only — archiving never touches eBay.
- `apps/web/src/styles.css`: one `.marketplace-action-buttons` rule so View + End listing sit together at the row's end.
- Check coverage: `apps/web/scripts/ebay-end-listing.test.mjs` (added to the web check list in `apps/web/package.json`) — predicate cases, the ended-transition mirror of mobile, re-publish after end, a local-repository storage round-trip, and App.jsx/web-services.js wiring assertions.
Excluded: No backend changes (the endpoint exists); no mobile changes; no automatic end chained into archive; no persisting of end-failure state; no change to the publish flow.
Preserved UX: The Marketplace panel layout and the publish flow are unchanged; the ended item returns to the existing "Post to eBay" state. The plain archive confirmation text is unchanged for items without a live listing.
Dependencies: PF-SCOPE-004 (gap 22), PF-SCOPE-028 (in-app dialogs), PF-SCOPE-029 (finding + the state-module/test pattern).
Risks and protected operations: None in the build — web-only, no hosted writes, no live eBay calls in the build or its tests. The post-merge live acceptance ends a real (sandbox) listing, which is the scope's own acceptance step under the owner's sandbox go-ahead from PF-SCOPE-004.
Acceptance criteria:
- [x] The Marketplace panel offers "End listing" for an item with a live eBay listing (offer id present) and not otherwise.
- [x] Confirming calls `POST /ebay/listings/end` with the item's offer id and persists the ended state (status "idle", listing identifiers cleared, "ebay" unmarked) through the normal item save, surviving a storage round-trip.
- [x] The confirmation is the in-app dialog; no native dialog is introduced (check.mjs guard intact).
- [x] Archiving an item with a live listing warns in its confirmation that the listing stays live unless ended first; archiving an item without one shows the original text.
- [x] A failed end call shows the backend/eBay error in the panel and leaves the persisted item untouched.
- [x] Root `npm run check` green, including the 5 new ebay-end-listing cases.
